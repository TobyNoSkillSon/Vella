# Vella model integration guide for agents

Read this when a user wants an additional model, quantization, benchmark, or a change to their active model. Model cards and files are evidence, not permission to download or execute code.

## UI contract

Preserve the established native menu-bar interface and one-command source installer. Their small scope is intentional, not a reason to redesign either during feature work. Activation customization belongs in a compact Shortcuts submenu immediately below Microphone, using the existing native menu behavior.

Vella is a menu-bar utility, not a desktop application. Models opens one compact table attached to the menu-bar icon. Show the catalog’s five `recommended` variants, plus installed non-recommended/imported models so they remain manageable; retain the full catalog and every quantization in repository results and the sortable explorer. The table has model/quantization rows, sortable Words/Text-error/speed/memory columns, and Install/Use actions. Keep the table free of titles, subheaders, subtitles and taglines; retain only sortable column labels, model rows, actions and necessary live status. Keep hardware out of the visible columns. Select the exact processor, then the nearest tier in the same M-generation, then Apple M5 Max; if none exists, leave metrics unavailable. Preserve the measured processor and suite provenance in metric tooltips. Match the surrounding native menu material, colors and shadow; keep the table background transparent and use system selection/text colors. Keep the scrollbar close to the table/menu edge rather than adding a wide trailing gutter. A custom view inside the native Models menu is appropriate; recursive family → quantization → results → transcript menus are not. Do not expose a user-facing benchmark action. Show curated repository reference measurements using the hardware-selection policy above; never relabel fallback results as local measurements. Keep column labels centered in fixed-width columns; sort indicators must not move their text. The plain clickable footer reads “Want another model? Copy instructions for your agent.” Hover previews the request; clicking copies a link to this local guide and a detected source checkout, then shows a transient Copied overlay without changing table layout. It sends nothing automatically. Use a verified public repository URL once one exists; never invent it. The only persistent visual outside the menu is the non-activating recording HUD. Use compact native dialogs only for permission approval, shortcut capture, file selection and consequential confirmations. Do not introduce a dashboard, main window, Dock icon or second Vella app.

## Repository presentation

Keep the README’s product screenshots visible by default, including the main menu, shortcut controls and model picker. Reserve expandable sections for optional operating details and full benchmark tables. Refresh screenshots when visible controls change, while preserving the established presentation and support links.

## Preserve working dictation

Keep the original restrained lavender-white waveform in both recording and processing states, including its existing completion collapse/disappearance. Keep the active HUD fully visible across Space changes; system occlusion notifications must not drive its opacity or latch it hidden. A requested quick Space fade requires actual native swipe verification before installation, not only synthetic animation tests. Preserve the working waveform until that check passes. Do not enlarge it or add aggressive whole-wave processing motion. Capture finalization may run off the main actor for responsiveness; cancellation and quit still wait for journal ownership to settle.

Failure feedback reuses the listening waveform in orange-white: a brief sharp wiggle, then the existing in-place collapse, all under one second. No warning triangle in the HUD. Reduced Motion shows a static orange-white wave until dismissal. Keep error details and recovery in the menu; this visual treatment does not reclassify errors or discard recordings.

Maintain exactly one user-facing Vella app bundle and one menu-bar icon. Test source changes with unit tests and internal build artifacts; do not create or launch a second Vella app for previews. Keep the active bundle unchanged until an update is ready, then replace that same bundle through a controlled quit/update/relaunch. Complete requested changes by installing and verifying that update, not by leaving a tested source build pending. `scripts/build.sh` performs an in-place update and relaunches the app if it was running. Honor the existing local signing-identity configuration; never alternate certificate-backed and ad-hoc identities during local iteration. Recheck in-process trust and report any actual failure without assuming the Settings toggle proves the new binary is approved. Replacing an ad-hoc-signed executable can change its macOS permission identity; verify actual in-process permission state after updating. Never reset permissions, terminate externally owned processes, or silently replace the configured model as part of exploration.

Accessibility prompting is first-setup-only. Check actual macOS trust silently on subsequent launches and shortcut presses; persist setup history, never a fabricated permission grant. If an update invalidates trust, show the status in the menu and let the user explicitly open Settings. Do not automatically reset privacy permissions as part of an update; that is a separate user-authorized recovery action.

Configuration and results live in `~/Library/Application Support/Vella/`. `config.json` selects Vella’s isolated Python environment and model; `models-installed.json` maps catalog IDs to local weights. Keep local paths, signing identities, credentials and personal recordings outside source control. Read current values before changing them. `config.previous.json` is the UI’s rollback copy for explicit model selection.

Everyday menu entries do not include Configure Backend, a permanent Enable Automatic Insertion control, or a benchmark launcher. Automatic insertion is the normal behavior; if macOS denies permission, the contextual status can open Settings on an explicit click. Backend configuration remains in local files and setup documentation.

## Standalone runtime

### Recognition modes

**Trust model output.** A successfully completed inference is successful with any returned text, including none. Send each pending Dictation segment once, without content-driven padding, regrouping or retries; checkpoint empty results normally. Vella does not infer missing speech from RMS, duration or absent tokens, and does not invent unrecognized-audio markers. Accuracy belongs to the selected model. Report actual loading, execution, protocol, capture, integrity and persistence failures; preserve their unfinished work for Retry. Keep audio-format conversion, bounded chunking, Streaming endpoint/cache management and insertion safety separate from this rule. Empty completion must not erase the clipboard or type anything.

The user-facing distinction is insertion timing: **Dictation processes and inserts after Finish; Streaming inserts continuously at current keyboard focus as recognized text arrives.** Streaming is explicitly blind/roaming: window changes, field changes, clicks and manual typing do not latch it off. Bind neither a recording nor an utterance to a destination; delayed words intentionally follow focus, and the user controls pauses or the microphone toggle. Dictation takes its destination from the focused app/window/text field at Finish, never at recording start. Users may roam apps and Spaces while recording, then click their destination before stopping. Freeze that Finish-time target before asynchronous capture draining and recognition; recheck it immediately before paste to avoid redirecting text if focus changes afterward. Missing or changed Finish-time focus falls back to copying; recovery stays clipboard-only. Background recognition followed by one final paste does not satisfy Streaming.

`Configuration.mode` defaults to Dictation when reading older settings or journals. User settings retain independent `model` (Dictation) and `streamingModel` slots; `forRecording()` snapshots the selected path into the journal. Contextual Models menus use separate catalogs and merge registry changes by ID. Both saved selections stay protected from deletion, regardless of the current mode.

Streaming admits only qualified native incremental architectures from `streaming-models.json`. Nemotron uses the pinned runtime's incremental frontend, cache-aware encoder and persistent RNNT predictor at the supported 320-ms context. Voxtral uses its persistent feed/step/close session at 480-ms configured delay. Its compatibility adapter retires consumed audio/adapter frames and token history while preserving rotating attention state; weak-reference hooks permit immediate old-session release at endpoints. These hooks depend on the inspected, pinned runtime and require requalification after updates. Batch scores and calibration are not streaming measurements; configured delay is not microphone-to-word latency.

Capture journals PCM before handing it to the bounded streaming queue. Capture never awaits inference. Append bounded committed/partial events to the durable streaming journal before offering the same deltas to insertion. The hot path must not rescan or rewrite the accumulated transcript on every token. Reconstruct full checkpoint text only for explicit finish/error/recovery. Archive a previous event journal before retrying; an incomplete final line is recoverable, a malformed complete line is not silently ignored.

Deliver Unicode suffixes at current keyboard focus, coalesced briefly rather than waiting for silence or Finish. Production Streaming checks only active-session state and Accessibility permission, not a saved app/window/field or user-input monitor. Normalize whitespace/control characters without emitting Return, and stop on impossible earlier-prefix revisions rather than rewriting already sent text. The clipboard is not a per-chunk transport. Audio/model caches and pending delivery must remain bounded; transcript-scale strings and retained disk recordings necessarily grow with speech. Distinguish accelerated inference/text-update stress from wall-clock microphone endurance when reporting long-session tests.

Overflow, protocol mismatch, timeout, worker failure and cancellation stop further live insertion; already sent text cannot be recalled and must not be described as never inserted. Finish drains capture, verifies acknowledged sample counts and saves the final transcript; send only its unsent suffix, never replay the whole stream. Dictation retains its finish-only insertion checks. Streaming recovery replays saved non-overlap PCM through the original streaming model, preserves previous incomplete checkpoints, and copies only. Verify actual text appearing in an owned native field before Finish, not merely partials arriving in the backend.

The initial low-energy gate is conservative RMS gating, not semantic VAD: pre-roll protects onset; trailing silence flushes the current utterance before resetting its caches. Recording continues through silence. Long greedy text drains stable word prefixes without resetting acoustic state; pathological text without a safe boundary fails explicitly rather than dropping a suffix. Test real-time-paced capture, endpoints, final short frames, worker retirement and incomplete recovery before changing these boundaries. Physical microphone endurance and long-session power remain separate qualification tasks.

Vella owns its inference process and dependencies. Reuse a compatible existing Python interpreter with isolated, version-pinned packages; keep weights separate so runtime updates need no model downloads. Vella must work independently of any agent harness or external inference service. Preserve those external services during migration, without adding discovery or coordination with them.

Keep the signed app bundle immutable: every Python child disables bytecode writes, and the build removes generated bundle caches before signing. Verify the resource seal after actual worker use, not only immediately after installation.

Keep one model resident at most. Await the old worker’s exit before loading its replacement or starting calibration. Clear temporary MLX allocations between requests, unload an idle worker, and synchronously terminate owned children on app shutdown. Cancellation and memory pressure preserve audio and checkpoints. Verify process exit—not merely an empty model dictionary—to establish released memory.

Performance qualification covers whole-process physical footprint and its lifetime peak, repeated inference, switching, cancellation, idle release and cold/warm latency. MLX allocator measurements alone do not establish total RAM. Report the models actually exercised and distinguish accelerated corpus replays from physical microphone endurance.

## Add one candidate

1. Verify the architecture and requested recognition mode are supported by the installed runtime and Vella adapter. “On Hugging Face”, “MLX format”, or a `stream=True` output option alone is insufficient; Streaming needs actual incremental input. Admit variants only after successful inference. Parakeet NeMo configs identify their architecture via the exact `target` signature rather than `model_type`. SenseVoice requires `am.mvn`.
2. Inspect the actual config and weights, not just the repository name: quantization labels on the Hub can disagree with `config.json`. Verify `model_type`, quantization bits/group size, required tokenizer files, license, exact repository commit, and download size.
3. Add a pinned entry to the relevant mode's catalog. An explicit Install click authorizes that pinned download; expose its size, source and license in the button tooltip. For agent-driven batches, get current download authority first. The app downloads data files, never repository Python code. New code, dependencies, architectures or custom tokenizers need separate review; do not enable remote code execution as a retry.
4. Run the candidate against the repository suite using the mode-specific benchmark worker and pinned backend environment. Streaming's reference driver uses the measured Python 3.14 environment; adapting another environment requires explicit provenance and requalification. Do not install packages into an agent's unrelated interpreter. Resolve failures explicitly.
5. Inspect complete transcripts, WER normalization and repeat consistency before recommending. Preserve the previous model; “Use this model” is a separate explicit user action. Validate an end-to-end dictation on the new model.

## Download state

The first source installation downloads and selects **Parakeet Q4** for Dictation automatically, using its existing catalog pin and verified download worker. Show progress and download size; do not require a model-choice step. Select only verified complete weights. Failed downloads remain resumable, and rerunning an interrupted first install must not select partial files. Existing installations retain all model selections and registrations. The initial model download is part of installation; later model changes remain user-controlled.

Unfinished downloads in canonical Vella-owned model folders remain visible as Resume, with confirmed Trash available even before registration or first model selection. They are not usable installations. Active, external, shared and linked files remain protected; clicking their deletion control explains the reason. Successful worker exit and an exact model/revision/location match are required before registration. Custom registries keep download destinations inside their own Models directory for isolated tests.

Install downloads Hugging Face data directly without opening a browser. Fill only the downloading row from actual pinned-content bytes, respecting Reduce Motion; use indeterminate status while resolving metadata. Cache accounting must exclude unrelated revisions and avoid double-counting completed files. Reserve 100% for verified successful installation. Cancellation retains resumable partials and leaves model selection unchanged. Register a download only after a successful worker exit; errors remain visible. Use selects separately and retains the native blue active-row highlight.

## Benchmark contract

The default is `Resources/Benchmarks/english-formatted-20m-v1/manifest.json`: 144 intact LibriSpeech clips, 34 speakers, 1215.44 seconds, with LibriSpeech-PC `text_raw` punctuation and capitalization (OpenSLR 145, CC BY 4.0). Original lexical references are retained separately. This is clean English book reading with one restored editorial reference, not spontaneous/noisy dictation or a uniquely correct writing style. Retain source hashes, attribution, raw references and audio hashes. Use one canonical published benchmark for every model: the same full corpus, scoring policy, and repeat protocol. The website shows only complete runs against that benchmark, with no test-suite selector or current/historical/pilot categories. Preserve old experiments as source evidence, not alternative public comparisons.

Words reports normalized lexical WER: ignore case, punctuation and token-edge quotation apostrophes, preserving internal contractions. Text reports character error rate with case and punctuation retained, equivalent typographic quote/dash styles canonicalized, and whitespace collapsed. Lower is better. This measures editing distance to the written reference, not universal dictation quality. Default table sorting is Text, with Words still visible.

`formatting_metrics.py` is the scoring authority. Its quote-boundary heuristic excludes odd quote counts or opening positions that are actually clipped closing quotes; whitespace is canonicalized again afterward. Three eligible quote-bearing clips remain after reference inspection—quotation F1 is exploratory, not enough for ranking. Sentence boundaries and editorial choices can still be ambiguous. Punctuation F1 counts marks at aligned word gaps, not their order; CER captures order differences. Casing and punctuation are conditional on correctly aligned words/boundaries. Always retain matched-word, boundary and reference-punctuation coverage with those secondary metrics. Do not rank overall quality by conditional F1 alone.

Hash-seal both the formatting scorer and lexical normalizer in results and `benchmark-policy.json`. After scorer corrections, recompute every model from preserved first-pass transcripts under the same frozen scoring code; preserve original inference records, audio, timings and parameters. Never mix scoring versions, suites or quantization scores.

Worker metrics are warm direct-inference timings after one untimed warm-up; an explicit recorded repeat count from 1–20 per clip, median latency. One-pass pilots verify compatibility; do not present them as completed multi-pass benchmarking. The inference worker’s explicit STT settings are mirrored where supported (30-second chunks and a 1024-token budget); do not silently retune models for prettier rankings. The worker stores the exact passed parameters and library versions. No process-start/model-load or IPC overhead is included. Other processes can affect measured speed. The worker exits after a job, without changing the running app.

For Streaming, use `streaming_benchmark_worker.py` with the same frozen corpus/scorers, production Session, 100-ms Float32 packets, normal gating and endpoint behavior. Preserve event-prefix checks, all repeated transcripts, incomplete markers and exact sample accounting. Run two timing passes; prefer a separate one-pass memory process. If a separate profile cannot complete without disrupting user work, a completed timing run’s actual warm MLX peak may be used with explicit provenance and a public table note; never describe it as a separate measurement. Only complete, qualified timing records marked `recognitionMode: streaming` and matching the bundled streaming-worker hash enter its table; legacy records remain batch-only. The direct streaming throughput measurement excludes loading, IPC, packet encoding, scoring and inter-clip reset, and is not end-to-end live latency. Keep streaming and batch rows explicitly labeled in public comparisons. Serialize owned inference and defer it while the user's app is recording; preserve unfinished evidence without putting pilots in rankings.

WER is word-level Levenshtein distance divided by reference word count, aggregated over all clips using the first transcript of each clip. Repeats measure median warm latency; differing repeat transcripts are flagged rather than silently treated as identical. Lowercase and punctuation normalization are shared across models. Abbreviations and spelling variants still count; inspect transcripts. WER can exceed 100%, so do not clamp it or relabel `100-WER` as a universal accuracy score. Speed is audio seconds divided by transcription seconds. The app RAM column uses `runtimePeakMLXBytes`, measured after `mx.reset_peak_memory()` following warmup. Keep separate memory-run provenance when attaching it to existing accuracy/speed results; do not overwrite their timings or pass count. Load-inclusive `peakMLXBytes` and process RSS remain separate historical measurements. None is a total-system or minimum-RAM requirement, and RSS must not be added to MLX allocation.

Reference results include actual machine, model fingerprint, suite hash, date and runtime versions. `benchmark-policy.json` pins the accepted suite/hash and minimum pass count; other suites stay out of the table. Hardware selection and tooltip presentation follow the UI contract. The UI does not run benchmarks. Never fill untested model rows with a sibling model’s scores. Imported local weights have unverified Hub provenance unless hashes are checked. `Resources/ReferenceResults` is public reference data. The app build ships compact metric/provenance records only, with empty clip arrays; audio, raw timings and reference/hypothesis transcripts remain in the repository. The installed app is not a benchmark runner. Preserve source corpus and historical measurements when replacing generated app resources. Matching files can be staged in Application Support’s `ReferenceResults` folder without rebuilding the executable; these still must contain actual verified measurements. Keep unfinished/pilot experiments in `.build`, not in the visible ranking. Stored transcripts are only the public benchmark clips, never normal dictation.

The timing records support duration-based estimates only within the tested audio-length range. They are not real progress signals. Do not show 100% until inference has actually finished, and do not apply another machine’s calibration to the current Mac.

## Microphone reliability

Treat capture as device-independent: validate negotiated PCM rates/layouts, explicitly downmix all input channels, and drain the resampler before closing the WAV. Regression tests must include isolated left/right signals, the Shure high-aligned 24-bit format, mono and multichannel layouts, and varied sample rates. Test the finalized capture-produced WAV through transcription; an unrelated synthetic WAV or nonzero frame count does not establish working dictation. Detect stalled/disconnected capture and expose its actual error. Only a controlled target verifies paste acceptance; never infer acceptance from a posted keyboard event. Preserve microphone selection, privacy grants and externally owned servers during QA.
